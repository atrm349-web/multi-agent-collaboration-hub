# 项目理解与阶段结论

日期：2026-11-02（Asia/Tokyo）。依据：用户提供的完整 V1.0 交接说明。

产品是本地单用户任务执行系统：自然语言目标经过规划、依赖调度、独立执行、结构化交接、审核、有限返工和验收，交付可追溯成果。核心必须能在没有特定厂商模型时保存、查看、取消和恢复调度状态。

第一版用两个独立 Codex 会话验证开发与审核，不将 ChatGPT Plus 当作 API 额度，不自动接入 Antigravity 个人会员会话。Antigravity 负责产品前端和浏览器验收；Codex 负责后端、执行器、存储及契约。

## 本轮范围

- 已读 Agetor、Shep 的实际源码，固定审查提交并安装冻结依赖。
- 已进行选定构建、单元/API 测试和真实 CLI 实验，详见 architecture-audit.md 与证据目录。
- 已设计七类实体、调度状态机、Adapter 能力声明、HTTP/SSE 契约和开发任务。
- 独立验证原型不修改候选仓库；正式复用路线仍需用户确认。

## 推荐

优先以 Agetor 为**有条件的复用底座**：保留其 Bun/SQLite、任务/运行记录、CLI JSONL 驱动和已有 HTTP/SSE；先改造权限策略与并行工作区，再扩展任务验收及调度。不能直接启用它的现有 Codex 自动执行作为安全 MVP。

Shep 是备选：已有更完整的工作流、检查点和消息总线，但功能面与依赖较大，Codex 执行器也需要先修权限策略。若 Agetor 权限改造无法通过测试，应重新评估 Shep，而不是强行采用 Agetor。此前 LangGraph 通用初选不构成本项目决定。

## 首版不扩大范围

不做远程节点、多用户 SaaS、复杂流程编辑器、Antigravity 自动控制、额外模型付费 API。Windows 只保留扩展方向，当前没有验证。

## 协作入口

桌面实际目录为 `./`。Codex 交接文件位于该目录的 `Codex/`；Antigravity 在自己的 `Antigravity/` 中写进度和意见。双方读取彼此文件，但不自动覆盖对方文件。文件共享不等于已建立实时通信或后台同步服务。
