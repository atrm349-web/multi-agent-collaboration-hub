## 四、发现（按严重度）

### P0-1　"演示模式"是诚实的，但"实机模式"把真假数据混在一起

我对比了两张截图（同一套 UI、同一个浏览器）：

**A. 你现在运行着的实例（`http://127.0.0.1:4321`，14:34 启动，数据库里 0 个真实任务）**
- 模式徽标：`● 演示`（紫色）
- 右上角明确写着：**"模拟数据 · 不调用 Agent"**
- 界面上的"智能门锁-国内外竞品调研"、5 个成员（Codex/ZCode/Devin/OpenCode/DSH）、6 条任务、甘特图，全部是演示数据

→ **这一档是诚实的**：它没有假装在做真实工作。截图：`evidence/ui-live-4321-current.png`

**B. 我跑真实任务时（14:42 冻结快照，端口 4340）**
- 模式徽标切换成 `实机运行`（绿色），任务头写着"🟢 真实多Agent协同 · 全链路打通"
- 右栏"产物"是**真实产物**（`duration.js`、`verify.js`、两份 test_report）
- 但左栏成员卡仍是 Codex/ZCode/Devin/OpenCode/DSH，且卡片上的任务里混着 demo 条目（T3 价格带分析、T4 专利检索、T6 撰写调研报告）
- 甘特图 5 条时间条（`✔ 3.2s` 等）仍是写死的

→ **这一档是问题所在**：同一屏里真产物和假成员/假任务混排，且只标了"实机"，没标"哪些是演示"。

**补充（并发改动提示）**：`apps/web/public/app.js` 在我跑完之后（14:45）又被改动过，成员卡已改为 DeepSeek / Claude / Gemini / WorkBuddy / Codex，并按真实子任务的 stage 分配；写死的 `deepseek-v3.2`、`gpt-5-codex` 已消失。但**当前跑着的 4321 实例是 14:34 启动的，前端在启动时被冻结进内存，所以它还在显示旧版**。要看到修复效果必须重启服务。

截至 14:45 的源码版本（`01810214…`）里仍有 **8 条写死甘特条**（`T1 抓取国内电商评论`、`✔ 3.2s`），所以"假数据"只修了一半。

### P0-2　默认配置的验收门可以被 Agent 自己改（未被触碰，仍存在）

`config/hub-config.json` 里默认仓库是 `examples/demo-geometry-repo`，三个测试档位跑的是仓库内的 `test_circle.js` / `test_rect.js` / `test_geom.js`。Agent 在这些仓库里是 `workspace-write`，**完全可以顺手把测试改宽**，验收就变成走过场。

对比：我这次把断言放在仓库外（`owner-tests/check.mjs` + `readPaths` 只读授权），Agent 改不到，所以那个 10/10 才有意义。产品要能投产，默认配置也必须是这个模式。

### P1-1　源码锁与 Git 历史已失效

`backend/agetor` 的 Git 历史被换成 4 条新提交（`initial release (Agent Router)` 起），`9f56aa45…` 已不存在；`docs/hub/frontend-source-lock.json` 仍是 11-03 的 `F02-r3` 记录。现在**无法用任何哈希去核对"这份代码是哪次签收的"**。要么补一份新 lock，要么删掉旧 lock 免得误导。

### P1-2　规划器产出的 7 步计划没被用上

`/tasks/decompose` 用真实 `deepseek-reasoner` 正常返回 7 个子任务（38 s），但我建任务时用的是显式计划——因为规划器给的 7 步里有测试/评审类步骤，会让同一条验收标准在"没写代码的步骤"上失败。也就是说：**规划器能用，但"规划→执行"之间还没有自动衔接**。这属于产品尚未闭环的一环，不是 bug。

### P2-1　空 diff 产物依旧存在

`FINAL-REVIEW-attempt-1.diff` 大小为 0（`e3b0c442…`），和 11-03 我在 S0 里提的观察一致，仍未修。

### P2-2　执行速度与"独立审查"的实际强度

实现+测试+审查合计约 22 秒。速度本身没问题，但意味着审查模型只用了很少时间看代码；本轮它确实批准了正确实现，但**审查强度**没有量化指标（比如它是否逐条比对验收标准）。

## 五、能不能投入使用

**分三种说法，别混：**

1. **作为"能真干活的本地执行引擎"——可以试用。**
本机单人、任务边界清楚、验收脚本由你放在仓库外，这套东西是能用的：真模型、真沙箱、真审批、真产物、原仓库不动，我这一轮全部实测到了。

2. **作为"给人看的多 Agent 协同大屏"——现在不行。**
界面上 5 个成员、6 个任务、甘特图都是假的，且没有 MOCK 标识。要么把这些面板接到真实 `agents` / `tasks` / `events` 数据，要么明确打上"演示数据"水印。否则任何演示都会被第一个问题问倒："这 5 个 Agent 是谁？"

3. **作为"生产级平台"——还差 5 件事**（按优先级）：
   1. 前端去假数据 / 明确标注；
   2. 默认配置的验收脚本移出 Agent 可写目录（或用 `readPaths` 只读授权）；
   3. 重做源码锁与版本基线（当前 Git 历史已换，旧锁失效）；
   4. 真实失败→返工在真实模型下跑一次（本轮一次通过，没验证到）；
   5. 并发 2 / 崩溃恢复 / 长时间运行的实际验证（`meta` 里已宣称 `parallel-execution`、`interrupted-recovery`，但没有对应证据）。
