## 二、失败是真的：模型首版只支持"空格分隔"，漏了"连写"

第一次 attempt 的验收输出（原文，来自 `rework_instruction`）：

```
PASS parseDuration("90s") === 90
FAIL parseDuration("1h30m"): expected 5400 — INVALID_DURATION
PASS parseDuration("2d") === 172800
FAIL parseDuration("1H30M"): expected 5400 — INVALID_DURATION
PASS parseDuration("1h 30m") === 5400
PASS parseDuration("1w") === 604800
FAIL parseDuration("2d4h"): expected 187200 — INVALID_DURATION
PASS parseDuration("1 h") threw RangeError(INVALID_DURATION)
PASS parseDuration("90") threw RangeError(INVALID_DURATION)
PASS parseDuration("1.5h") threw RangeError(INVALID_DURATION)
PASS parseDuration("-5m") threw RangeError(INVALID_DURATION)
PASS parseDuration("abc") threw RangeError(INVALID_DURATION)
PASS parseDuration("999999999999999999999s") threw RangeError(INVALID_DURATION)
```

从它交付的 attempt-1 源码可以确认原因：它用 `text.split(" ")` 切段，所以 `1h 30m`（带空格）能过，而 `1h30m`（连写）被当成一个非法段拒掉了。**这是读规格时漏掉了"允许连写"这一条**，不是环境问题、不是替身故障。

## 三、返工链路是通的

1. **触发依据是真实退出码**：`validation AC-DURATION failed / exit 1`，不是模型自称失败。
2. **第二次拿到了失败证据**：`rework_instruction.content` 里带着整段测试 stdout（含 `expected 5400` 与 `FAIL` 行），模型据此只改这一处。
3. **第二次从失败提交继续**：`hub_workspaces` 里 attempt 1 / attempt 2 的 commit 不同（S0 已验证同一路径，本轮同样成立）。
4. **第二次通过**：`validation AC-DURATION passed / exit 0`（13/13）。
5. **独立审查**：FINAL-REVIEW 用了另一个 provider session，先于审批完成。
6. **审批后才是成功**：Task 在 `waiting_approval` 时不算成功，审批后 `succeeded`。
