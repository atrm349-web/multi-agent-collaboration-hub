### 三条具体修改建议（给 Codex，属于 `scripts/start-hub.ts` 的小改）

1. **T5-1**：把 `throw new Error('Official Codex CLI is required')` 改成带指引的版本，例如
   `Official Codex CLI is required (not found on PATH). Install it or add its directory to PATH, then run 'codex login status'.`
   —— 这台机器上 codex 只存在于 `/Applications/ChatGPT.app/Contents/Resources/codex-cli/bin`，不加 PATH 必失败，而现有提示不会告诉用户这件事。
2. **T5-3**：把端口探测放到所有 DB 操作**之前**。现在 `HubService` 构造（含迁移与 owner 行）先执行，`Bun.serve` 后执行；端口冲突时 DB 已被初始化。建议在 `mkdir(root)` 之后立刻做一次 `Bun.serve` 试探或 `lsof` 检查，失败即退出。这不是功能缺陷，但"启动失败却已改状态"会让后续排障困惑。
3. **T5-4 / T5-5**：把配置读取包一层：
   ```ts
   let config; try { config = JSON.parse(await readFile(configPath,'utf8')); }
   catch (e) { throw new Error(`Cannot read hub config at ${configPath}: ${(e as Error).message}`); }
   ```
   现在用户看到的是一屏 Bun 栈，不是"配置文件坏了"。

## 采样工具可用性（写入计划修订）

| 工具 | 受限沙箱 | 说明 |

| `footprint -p <pid>` | ✅ | 能拿到 `phys_footprint`，T1 就是用它 |
