             → 自动返工（rework_instruction 里带完整失败输出：expected "¥12.34" but got "12.34"）

四个关键确认：

1. `run.status=succeeded` 但 `validation.status=failed` 同时存在——**模型进程成功≠实现被接受**，这正是设计要证明的点；
2. 返工消息确实把失败测试的 stdout/exitCode 带给了第二次 attempt；
3. 第二次 attempt 的 `commit_sha` 与第一次不同，说明"从失败提交继续"的依赖路径是活的；
4. 产物、审批摘要、3 个不同 session 全部符合 `captureFinalDelivery` 的约束。

顺带一个小观察：`FINAL-REVIEW` 即使零改动也会生成一份空 diff 产物（sha256 `e3b0c442…`），把 `artifactCount` 抬高。纯展示问题，已写进 `S0-offline-loop/README.md` 第 3 节。

**S0 的边界**：provider 是模拟器、planner 被绕过、testRunner 用直接 node 代替 seatbelt。它证明"失败发生时返工链路完整可观测"，**不证明**真实模型会失败/会修复——那只有 S1 能回答。
